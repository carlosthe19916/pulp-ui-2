# Plugins

A plugin's facts and every piece of UI the generic pages render for it live in its folder,
`client/src/plugins/<id>/`, in two layers: a **definition** (facts about Pulp) and a **UI** (how
the app presents them). Generic pages (hosts) render per-plugin pieces through two registries and
never branch on a plugin. (Plugin-only pages and their queries, such as Ansible collections or
container namespaces, still live in `app/`.)

```
client/src/
  plugin-sdk/                  # the plugin contract (never imports plugins or registries)
    definition/                # definePlugin, createCatalog, the definition types
    ui/                        # definePluginUi, PluginUi<D>, GENERIC, lazyViews, contracts
  app/components/ContentPanelLayout/  app/components/BrowseShell/
                               # app building blocks plugin panels and Browse views reuse
  plugins/
    catalog.ts                 # @catalog: PLUGIN_DEFINITIONS and the pure lookups
    registry.ts  index.ts      # @plugins: PLUGIN_UI and the UI lookups hosts call
    rpm/
      definition.ts            # definePlugin({...}): facts only
      ui/index.ts              # definePluginUi({ definition: rpm, ui: {...} })
      ui/forms/  ui/content/  ui/browse/  ui/tabs/  ui/actions.ts
```

## Definition or UI

The litmus: **would it change if the UI were redesigned?** Then it's UI.

- **Definition** (`definition.ts`, `definePlugin`): the packages that mean it's installed, its
  types per entity keyed by `pulp_type` with their `apiPath`, what a repository syncs from and
  publishes to, `contentChanges`, `archiveImport`, `scan`, `rolesManaged`, action endpoints
  (`path`, `target`, `repositoryParam`), content types (`apiPath`, `upload`), the ACS endpoint.
  It imports only `@plugin-sdk/definition` (and generated types).
- **UI** (`ui/`, `definePluginUi`): labels, forms, content panels, Browse sections, the
  repository tab, client setup snippets, action labels and fields, upload fields, content
  search, nav pages, the ACS label.

## Type-checked completeness

- `definePlugin` keeps the `pulp_type`s literal. `apiPath` must be a collection in the OpenAPI
  spec (`pulpTypes.gen.ts`, generated by `npm run generate`), and `compatibleRemoteTypes` /
  `compatiblePublicationTypes` must be the plugin's own types.
- `PluginUi<D>` is derived from the definition: one entry per declared type, every piece a
  required key. An uploadable content type must have `upload` and a read-only one can't; a
  `search.param` must be a filter of its list endpoint; each declared action needs its UI.
- Opting out is explicit: `GENERIC` where the host has a generic view (`panel`, `browse`,
  `clientSetup`), `null` where the piece can be absent (`tab`, `search`). A type's `label`
  is optional and defaults to the plugin's.
- Forms are typed from the definition: `remoteForm(rpm.remote["rpm.uln"])(({ f, s }) => …)`
  edits that collection's create body (the update body when Pulp can't create it).
- `@plugins` maps every plugin id in `PLUGIN_DEFINITIONS` to its UI: a definition without one
  fails to compile.

## Hosts

- Pages and components read facts from `@catalog` (`getPulpType`, `getAvailableTypes`,
  `getContentType`, …) and UI from `@plugins` (`getEntityForm`, `getContentPanel`,
  `getRepositoryBrowse`, `getRepositoryTab`, `getRepositoryActions`, `getClientSetup`,
  `getContentSearch`, `getUploadFields`, `getPluginPages`, `useCreateTypeSelect`), never
  `pulp_type` string comparisons, plugin `switch` chains or a plugin's files.
- Panels, Browse views and tabs are lazy (`lazyViews(() => import("./browse/X"))("XView")`);
  hosts render them inside `Suspense`.
- Plugin actions run through `RepositoryActionModal` with the `IPluginAction` the registry
  returns (endpoint, label and fields together); no per-action modal.

## Adding a plugin

Write `plugins/<id>/definition.ts`, add it to `PLUGIN_DEFINITIONS`, add `<id>: <id>Ui` to
`PLUGIN_UI`; the compiler then lists every missing UI piece. The `add-plugin` skill walks
through it.

## Checklist

Pass/fail rubric for `/eval`.

- [ ] A plugin's code sits in its own `plugins/<id>/` folder; its `definition.ts` holds only
      facts and imports only `@plugin-sdk/definition`; its `ui/` never imports `@plugins`, a
      host or another plugin.
- [ ] `plugin-sdk/**` imports no plugin and no registry.
- [ ] New per-type behaviour is a definition field or a `PluginUi` piece with an explicit
      opt-out, not a new `pulp_type`-keyed map elsewhere.
- [ ] Hosts read plugin facts from `@catalog` and UI from `@plugins`; no new
      `pulpType === "<plugin>.<type>"` comparisons, plugin `switch` chains or imports of a
      plugin's files.
- [ ] Forms are typed with `remoteForm` / `repositoryForm` / `distributionForm` /
      `publicationForm` from the plugin's definition, not a hand-picked body type.
- [ ] Panels, Browse views and tabs are lazy views rendered inside `Suspense`.
