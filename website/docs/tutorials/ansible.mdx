# Ansible Galaxy server

The job is a private Galaxy: the collections you choose to mirror, often certified content from Red Hat Automation Hub, plus collections you publish. Public `galaxy.ansible.com` is the same mechanism with no token.

```text
ansible-galaxy --> Pulp --+-- listed collections   sync, immediate
                          +-- ansible-hosted       ansible-galaxy collection publish
```

There is no on-demand download and no pull-through cache. A sync copies the collections named in **Requirements**, now. An empty requirements list tries to mirror the whole server.

You need Pulp with `pulp_ansible`, ansible-core 2.15+, and [`examples/ansible`](https://github.com/carlosthe19916/pulp-ui-2/tree/main/examples/ansible). The client URL is `<pulp>/pulp_ansible/galaxy/<domain>/<base-path>/`. `ANSIBLE_API_HOSTNAME` on the server must be the URL clients use, or that URL shows the container hostname. See [Tutorials](./index.md#settings-the-local-backend-already-has).

## Sync a list

A collection remote syncs with the `immediate` policy only.

| Field | What it does |
| ----- | ------------ |
| URL | Galaxy API, `https://galaxy.ansible.com/api/`, or a hub such as `https://console.redhat.com/api/automation-hub/content/published/`. |
| Requirements | The collections to mirror. This is the set. |
| Sync dependencies | On pulls what those collections depend on. |
| Highest versions to sync | The N newest of each collection. Empty syncs every version. |
| Signed collections only | Mirror only versions that carry a signature. |
| Token and SSO URL | Automation Hub. Galaxy needs neither. The token is the hub offline token. The SSO URL is where it is exchanged. |

```yaml title="Requirements"
collections:
  - name: ansible.posix
    version: ">=2.0.0"
  - name: redhat.rhel_system_roles
```

Attach the remote to an Ansible repository and sync. Serve the repository with an Ansible distribution.

## Publish, and the order of servers

There is no group repository. `server_list` is the order `ansible-galaxy` tries.

```ini title="ansible.cfg"
[galaxy]
server_list = pulp_hosted, pulp_upstream

[galaxy_server.pulp_hosted]
url = http://localhost:5003/pulp_ansible/galaxy/default/ansible-hosted/
username = admin
password = password

[galaxy_server.pulp_upstream]
url = http://localhost:5003/pulp_ansible/galaxy/default/ansible-upstream/
username = admin
password = password
```

The local backend requires credentials to read the Galaxy API. A server that allows anonymous reads only needs them on the server you publish to.

```bash
cd examples/ansible
ansible-galaxy collection build hello-collection
ansible-galaxy collection publish -s pulp_hosted example-hello-1.0.0.tar.gz
ansible-galaxy collection install -r playbook/requirements.yml
ansible-playbook -i localhost, playbook/site.yml
```

## Other sources, promotion, trust

| Remote | When |
| ------ | ---- |
| Ansible collection | A Galaxy v3 API. The usual case. |
| Ansible role | Legacy Galaxy v1 roles. `ansible-galaxy role install -s <url>`. |
| Ansible (Git) | The collection exists only in Git. Set the URL and a ref. **Metadata only** indexes without downloading artifacts. |

**Copy collection version** leaves it in the source, which is staging to release. **Move collection version** removes it from the source. If the Galaxy metadata looks stale after either, **Rebuild metadata**.

**Mark** adds a label such as `certified` that clients can filter on. **Unmark** removes it. Marks, deprecations, namespaces and roles are labels or synced content. You do not upload them as files.

**Sign collections** uses a [signing service](../concepts/operating.md#signing) on the server. Verifying a mirror is **Signed collections only** on the remote.

:::info[Not in this plugin]

An on-demand pull-through cache of Galaxy or Automation Hub. Pulp Ansible syncs the requirements list. Listing what you need is the set.

:::

## Troubleshooting

| Symptom | Cause and fix |
| ------- | ------------- |
| `Could not satisfy the following requirements` | The collection is not in the mirror, or the server rejected an anonymous read. Add it to **Requirements** and sync, or set credentials. |
| `401` on publish | That `ansible.cfg` server has no `username` / `password` or token. |
| `Collection ... already exists` | That version is already in the repository. Bump `version` in `galaxy.yml`. |
| Client URL shows the wrong host | Set `ANSIBLE_API_HOSTNAME`. |
| A sync tries to download all of Galaxy or the hub | **Requirements** is empty. |
