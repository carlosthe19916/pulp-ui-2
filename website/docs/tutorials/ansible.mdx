# Ansible Galaxy server

Set up Pulp the way you would set up Nexus, Artifactory or a private Automation Hub for Ansible: a mirror of the Galaxy collections you depend on, a hosted server for your own collections, and `ansible-galaxy` installing from both.

```text
ansible-galaxy --> Pulp --+-- ansible-upstream  mirror of listed collections --> galaxy.ansible.com
                          +-- ansible-hosted    hosted
```

| Nexus / Artifactory        | Pulp                                                                                          |
| -------------------------- | --------------------------------------------------------------------------------------------- |
| Proxy (remote) repository  | Collection remote with a **Requirements** list + repository, **Sync**ed                       |
| Hosted (local) repository  | Repository + distribution; `ansible-galaxy collection publish` uploads to it                  |
| Group (virtual) repository | Not available; list both servers in `ansible.cfg`, which tries them in order                  |
| "Set me up"                | **Client setup** snippet (`ansible.cfg`) on distributions, **Install** snippet on collections |

Pulp has no pull-through cache for Ansible: you **sync** the collections listed in the remote's **Requirements**, with their dependencies.

## Prerequisites

- Pulp UI connected to a Pulp server with `pulp_ansible`, signed in as a user who can create Ansible repositories (see [Tutorials](./index.md#before-you-start))
- ansible-core 2.15 or later
- The example in [`examples/ansible`](https://github.com/carlosthe19916/pulp-ui-2/tree/main/examples/ansible): `hello-collection`, the `example.hello` collection you publish, and `playbook`, which uses it

The URLs below are for the local backend. Galaxy URLs have the form `<pulp>/pulp_ansible/galaxy/<domain>/<base-path>/`; the distribution page shows yours as its client URL. On another server, `ANSIBLE_API_HOSTNAME` must be the URL clients use (see [Tutorials](./index.md#non-local-servers)).

:::tip[In a hurry?]

`examples/ansible/setup.sh` creates every Pulp object of steps 1 and 2 through the REST API, and `examples/ansible/demo.sh` runs steps 3 to 6. See [Run the examples](./index.md#run-the-examples).

:::

## 1. Mirror collections from Galaxy

1. **Content Management → Remotes → Create remote.** Type **Ansible collection**, name `ansible-upstream`, URL `https://galaxy.ansible.com/api/`. In **Requirements**, list what to mirror:

   ```yaml
   collections:
     - name: ansible.posix
       version: ">=2.0.0"
   ```

   Keep **Sync dependencies** on so the collections they need come along.

   ![Create Ansible collection remote form](/img/tutorials/ansible/remote-create.png)

2. **Repositories → Create repository.** Type **Ansible**, name `ansible-upstream`, remote `ansible-upstream`.
3. On the repository page, **Actions → Sync**. **Content → Browse** then lists the mirrored collection versions.
4. **Distributions → Create distribution.** Type **Ansible**, name and base path `ansible-upstream`, repository `ansible-upstream`.

:::warning

With `galaxy.ansible.com` and no requirements, a sync downloads every collection on Galaxy. Always list what you need.

:::

## 2. Host your own collections

Create a repository and a distribution named `ansible-hosted`, as in step 1 but without a remote. The distribution page shows the server URL and an `ansible.cfg` snippet:

![Ansible distribution details with the Galaxy server URL and ansible.cfg snippet](/img/tutorials/ansible/dist-detail.png)

## 3. Configure ansible-galaxy

```ini title="ansible.cfg"
[galaxy]
server_list = pulp_hosted, pulp_upstream

[galaxy_server.pulp_hosted]
url = http://localhost:5003/pulp_ansible/galaxy/default/ansible-hosted/
username = admin
password = password

[galaxy_server.pulp_upstream]
url = http://localhost:5003/pulp_ansible/galaxy/default/ansible-upstream/
username = admin
password = password
```

`ansible-galaxy` looks for each collection on the servers in `server_list` order. The local backend requires credentials to read its Galaxy API; on a server that allows anonymous reads, only the hosted server needs them, to publish. The example's `demo.sh` points the same server names at your Pulp with `ANSIBLE_GALAXY_SERVER_<NAME>_URL` variables.

## 4. Publish your collection

```bash
cd examples/ansible
ansible-galaxy collection build hello-collection
ansible-galaxy collection publish -s pulp_hosted example-hello-1.0.0.tar.gz
```

```text
Publishing collection artifact 'example-hello-1.0.0.tar.gz' to pulp_hosted http://localhost:5003/pulp_ansible/galaxy/default/ansible-hosted/api
Collection has been successfully published and imported to the Galaxy server pulp_hosted http://localhost:5003/pulp_ansible/galaxy/default/ansible-hosted/api
```

Open `ansible-hosted` → **Content → Browse** and select the collection for its contents and **Install** snippet:

![example.hello in the ansible-hosted repository with its install snippet](/img/tutorials/ansible/package.png)

## 5. Install through Pulp

`example.hello` depends on `ansible.posix`. Installing it pulls one from each server:

```bash
ansible-galaxy collection install -r playbook/requirements.yml
```

```text
Installing 'example.hello:1.0.0' to '.../ansible_collections/example/hello'
example.hello:1.0.0 was installed successfully
Installing 'ansible.posix:2.2.2' to '.../ansible_collections/ansible/posix'
ansible.posix:2.2.2 was installed successfully
```

## 6. Run the playbook

```bash
ansible-playbook -i localhost, playbook/site.yml
```

```text
TASK [Print the greeting] ******************************************************
ok: [localhost] => {
    "msg": "Hello, Pulp!"
}
```

## Going further

### Promote between repositories

Copy a tested collection version from a staging repository into a release repository with **Actions → Copy collection versions**, or move it with **Move collection versions**.

### Signing and deprecation

**Sign collections** signs collection versions with a signing service configured on the server, and **Signed collections only** on a remote mirrors only signed versions. See [Signatures](https://pulpproject.org/pulp_ansible/docs/user/guides/signature/).

### Versions and rollback

Every sync or publish creates a new repository version (**Versions** tab). Edit the distribution and choose **Serve → Repository version** to freeze what clients see.

### Access control

Publishing requires a user who can modify the repository; see [Access management](../administration/roles-and-permissions.md).

## Troubleshooting

| Symptom                                                                  | Cause and fix                                                                                                                                                     |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Could not satisfy the following requirements` for a mirrored collection | The server rejected an anonymous read, or the collection isn't in the mirror. Add credentials to that server, or add the collection to **Requirements** and sync. |
| `401` on publish                                                         | No credentials for the hosted server. Set `username`/`password` or a `token` in its `ansible.cfg` section.                                                        |
| `Collection ... already exists`                                          | That version is already in the repository. Bump `version` in `galaxy.yml`.                                                                                        |
| Client URL shows the container's hostname                                | Set `ANSIBLE_API_HOSTNAME` on the Pulp server to the URL clients use.                                                                                             |

## Clean up

Delete the two distributions, then the two repositories, then the `ansible-upstream` remote, each from its list's row actions. Stored collections are freed by Pulp's [orphan cleanup](https://pulpproject.org/pulpcore/docs/user/guides/reclaim-disk-space/) task.
