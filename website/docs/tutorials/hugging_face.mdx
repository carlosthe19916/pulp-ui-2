# Hugging Face model cache

One job: the first download of a model or dataset is fetched from the Hub and then served from Pulp, including gated models when the remote has a token that can read them.

```text
hf / huggingface_hub --> Pulp -- hf-proxy  pull-through --> huggingface.co
```

Pull-through is the only mode `pulp_hugging_face` supports. There is no sync and no repository to create. Hub API calls (model info, file lists) are forwarded to the Hub. The files are stored in Pulp.

Hosting your own models is not in this plugin. Share those files from a [file repository](./file.mdx).

You need Pulp with `pulp_hugging_face`, and `huggingface_hub` (the `hf` CLI). [`examples/hugging_face`](https://github.com/carlosthe19916/pulp-ui-2/tree/main/examples/hugging_face) downloads `hf-internal-testing/tiny-random-bert`, a tiny test model. `setup.sh` creates the remote and the distribution.

| Object | What matters |
| ------ | ------------ |
| Remote `hf-proxy` | URL `https://huggingface.co`, policy **On demand**. **Access token** for a private or gated model. |
| Distribution `hf-proxy` | No repository. Pull-through remote `hf-proxy`. |

```bash
export HF_ENDPOINT=http://localhost:5003/pulp/content/default/hf-proxy
hf download hf-internal-testing/tiny-random-bert config.json
```

No trailing slash. `transformers` and `datasets` read `HF_ENDPOINT` too.

The plugin has no per-object roles. Grant its global roles. See [Who can push](../concepts/access-control.md). Reads of the content URL are anonymous until the distribution has a content guard.

## Troubleshooting

| Symptom | Cause and fix |
| ------- | ------------- |
| Downloads still go to huggingface.co | `HF_ENDPOINT` is unset in that process. |
| `401` or `403` for a model | The model is private or gated. Set **Access token** on the remote. |
| `404` for every file | The distribution has no pull-through remote. |
