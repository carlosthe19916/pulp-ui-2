# RPM repository manager

Mirror a distribution (Fedora, EPEL, RHEL, Oracle Linux) and promote the set you want clients to install. Uploading a single RPM is how you add your own package to that set. It is not the reason to run Pulp.

```text
dnf --> Pulp --+-- rpm-upstream  on-demand mirror --> a distro repository
               +-- rpm-releases  the set you promote
```

There is no pull-through cache. You sync. With **On demand**, the sync downloads metadata now and each package on the first `dnf` request. [Export](../concepts/disconnected.md) needs `immediate` so the bytes exist. A closer mirror for those on-demand bytes is an alternate content source, on the same page.

You need Pulp with `pulp_rpm`, and `dnf` (or a Fedora container). [`examples/rpm`](https://github.com/carlosthe19916/pulp-ui-2/tree/main/examples/rpm) mirrors the tiny fixture `https://fixtures.pulpproject.org/rpm-unsigned/` and builds `hello-pulp`. For a real mirror use the distro, for example `https://dl.fedoraproject.org/pub/epel/9/Everything/x86_64/`. The remote URL is the directory that contains `repodata/`.

## Mirror a distro

| Object | What matters |
| ------ | ------------ |
| Remote | Policy **On demand**. An **ULN** remote is a different type: Oracle Linux channels, with Oracle credentials, not a plain URL. |
| Repository | That remote, and **Auto-publish**. Without a publication, `dnf` 404s on `repodata`. |
| Distribution | The repository, and **Generate a .repo file**. |

```bash
sudo curl -o /etc/yum.repos.d/rpm-upstream.repo \
  http://localhost:5003/pulp/content/default/rpm-upstream/config.repo
```

```ini title="/etc/yum.repos.d/rpm-hosted.repo"
[rpm-hosted]
name=rpm-hosted
baseurl=http://localhost:5003/pulp/content/default/rpm-hosted/
repo_gpgcheck=0
gpgcheck=0
enabled=1
```

`gpgcheck=0` is for unsigned fixtures. With signed packages, set **Client repo config** on the repository so the generated file carries `gpgkey` and `gpgcheck=1`. The signing service itself is [registered on the server](../concepts/operating.md#signing). The repository selects `metadata_signing_service` (signs `repomd.xml`), `package_signing_service`, and the package signing fingerprint. There is no separate sign action. Publish, or add content with auto-publish, so the next version is signed.

## Promote

Copy between repositories copies references, not bytes.

**Add content** from another repository copies the packages you pick.

**Advanced copy** also solves dependencies. The UI takes a JSON list of instructions:

```json
[
  {
    "source_repo_version": "<href>",
    "dest_repo": "<href>",
    "content": ["<package href>"]
  }
]
```

:::info[Not yet in Pulp UI]

A package picker for advanced copy, so you choose packages instead of pasting hrefs. Until then, build this `config` or use the [Pulp API](https://pulpproject.org/pulp_rpm/docs/user/guides/copy-content/).

:::

Point the release distribution at a repository version to freeze what `dnf` sees while the next sync lands in staging. See [What clients see](../concepts/what-clients-see.md).

## What a client can see besides RPMs

| Content | How it arrives |
| ------- | -------------- |
| Packages | Upload the `.rpm`, or sync. |
| Advisories (errata) | Upload the advisory JSON. |
| Package groups | Upload a `comps.xml`. **Replace existing comps content** overwrites; otherwise Pulp merges. |
| Module streams, categories, environments, langpacks, kickstart trees | Sync only. They are view-only. |

:::info[Not yet in Pulp UI]

An advisory form (CVEs, severity, affected packages). Prepare the JSON and upload it, or use the [advisory API](https://pulpproject.org/pulp_rpm/docs/user/guides/upload-advisory/).

:::

There is no `dnf` command to publish an RPM. Upload it. Auto-publish regenerates the metadata.

## Keep the mirror small, and see the CVEs

**Retain package versions** on the repository keeps the newest N versions of each package. **Retain repo versions** keeps the newest N repository versions. A version a distribution is serving is kept. **Prune packages** is the one-off: `keep_days` (default 14) and `dry_run` to preview. It keeps the newest of each package and creates a new version. [Orphan cleanup](../concepts/disk.md) is what frees the bytes afterwards.

Vulnerability scanning reports and does not remove packages. Scan one repository version on demand, or set the repository's vulnerability scanning so each sync scans the new version. The report is on the scanned version. Promote or prune to drop what you will not ship.

## Troubleshooting

| Symptom | Cause and fix |
| ------- | ------------- |
| `404` for `repodata` | The repository has no publication. Turn on **Auto-publish**, or publish. |
| A package from the mirror is not installed | On demand has not fetched it yet, or the remote is gone. On-demand bytes 404 when the upstream is unreachable. See [When bytes are fetched](../concepts/download-policies.md). |
| `gpgcheck` fails on the fixture | The packages are unsigned. `gpgcheck=0` until you select a signing service and publish again. |
