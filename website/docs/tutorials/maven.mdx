# Maven repository manager

Cache Maven Central for every build, and publish your own releases and snapshots to Pulp. Release and snapshot are two repositories by convention. Pulp does not enforce a release policy, and it does not offer a group repository: `settings.xml` lists each one.

```text
mvn / gradle --> Pulp --+-- maven-central    pull-through --> Maven Central
                        +-- maven-releases   hosted
                        +-- maven-snapshots  hosted
```

You need Pulp with `pulp_maven`, JDK 17, Maven 3.9, and the projects in [`examples/maven`](https://github.com/carlosthe19916/pulp-ui-2/tree/main/examples/maven) (`hello-lib` publishes, `hello-app` consumes). `examples/maven/setup.sh` creates the Pulp objects. URLs below are the local backend (`http://localhost:5003`, domain `default`).

## Cache Maven Central

Three objects, and the remote hangs on the **distribution**, not the repository:

| Object | What matters |
| ------ | ------------ |
| Remote `maven-central` | URL `https://repo1.maven.org/maven2/`. |
| Repository `maven-central` | Leave its remote empty. |
| Distribution `maven-central` | Base path `maven-central`, repository `maven-central`, pull-through remote `maven-central`. |

The first request for an artifact downloads it once, stores it, and adds it to the repository as a new version. Later requests are served from Pulp, including when Maven Central is unreachable, until you remove the remote.

## Publish releases and snapshots

A hosted repository plus a distribution, with no remote, for `maven-releases` and again for `maven-snapshots`. Use the repository name as the base path.

Each hosted repository has two URLs:

| Purpose | URL | Keyed by |
| ------- | --- | -------- |
| Read (resolve) | `http://localhost:5003/pulp/content/default/maven-releases/` | Base path |
| Write (`mvn deploy`) | `http://localhost:5003/pulp/maven/default/maven-releases/` | Repository name |

The deploy URL is `<pulp>/pulp/maven/<domain>/<repository-name>/`. Without domains, drop `<domain>/`.

```xml title="~/.m2/settings.xml"
<settings>
  <servers>
    <server>
      <id>pulp-releases</id>
      <username>admin</username>
      <password>password</password>
    </server>
    <server>
      <id>pulp-snapshots</id>
      <username>admin</username>
      <password>password</password>
    </server>
  </servers>
  <mirrors>
    <mirror>
      <id>pulp-central</id>
      <url>http://localhost:5003/pulp/content/default/maven-central/</url>
      <mirrorOf>central</mirrorOf>
    </mirror>
  </mirrors>
  <profiles>
    <profile>
      <id>pulp</id>
      <repositories>
        <repository>
          <id>pulp-releases</id>
          <url>http://localhost:5003/pulp/content/default/maven-releases/</url>
          <snapshots><enabled>false</enabled></snapshots>
        </repository>
        <repository>
          <id>pulp-snapshots</id>
          <url>http://localhost:5003/pulp/content/default/maven-snapshots/</url>
          <releases><enabled>false</enabled></releases>
          <snapshots><updatePolicy>always</updatePolicy></snapshots>
        </repository>
      </repositories>
    </profile>
  </profiles>
  <activeProfiles>
    <activeProfile>pulp</activeProfile>
  </activeProfiles>
</settings>
```

`mirrorOf` must be `central`, or `*,!pulp-releases,!pulp-snapshots`. `*` also sends your hosted repositories to the cache. Encrypt the password with [`mvn --encrypt-password`](https://maven.apache.org/guides/mini/guide-encryption.html). The example [`settings.xml`](https://github.com/carlosthe19916/pulp-ui-2/tree/main/examples/maven/settings.xml) reads values from the environment.

`hello-lib` declares the deploy URLs. The `<server>` id and the `distributionManagement` id are the same string:

```xml title="hello-lib/pom.xml"
<distributionManagement>
  <repository>
    <id>pulp-releases</id>
    <url>http://localhost:5003/pulp/maven/default/maven-releases/</url>
  </repository>
  <snapshotRepository>
    <id>pulp-snapshots</id>
    <url>http://localhost:5003/pulp/maven/default/maven-snapshots/</url>
  </snapshotRepository>
</distributionManagement>
```

```bash
cd examples/maven/hello-lib
mvn package
mvn deploy -Drevision=1.0.1-SNAPSHOT
mvn deploy -Drevision=1.0.0
rm -rf ~/.m2/repository/org/example/pulp
cd ../hello-app && mvn -q compile exec:java
```

Gradle lists the content URLs, not the deploy URLs. `isAllowInsecureProtocol` is only for plain `http://`:

```kotlin title="build.gradle.kts"
repositories {
    maven { url = uri("http://localhost:5003/pulp/content/default/maven-central/"); isAllowInsecureProtocol = true }
    maven { url = uri("http://localhost:5003/pulp/content/default/maven-releases/"); isAllowInsecureProtocol = true }
}
```

## What the form does not say

- A second deploy of an existing release **replaces** the files in a new repository version. Deploy to a staging repository and copy into `maven-releases` when a release must stay immutable. Copy copies references, not bytes.
- Point the distribution at a repository version to freeze what clients resolve. Point it back at the repository to follow the latest version. See [What clients see](../concepts/what-clients-see.md).
- Deploys need a user who can modify that repository. See [Who can push](../concepts/access-control.md).
- **Repair metadata** regenerates `maven-metadata.xml`. **Build path index** and **Compact path index** maintain the lookup index. Neither is a re-sync. See [Maven metadata](https://pulpproject.org/pulp_maven/docs/user/guides/metadata/).

## Troubleshooting

| Symptom | Cause and fix |
| ------- | ------------- |
| `401 Unauthorized` on deploy | The `<server>` id does not match `distributionManagement`. |
| `403 Forbidden` on deploy | That user cannot modify the repository. |
| `404` on deploy | The URL used the content base path. Use `/pulp/maven/<domain>/<repository-name>/`. |
| Your artifacts are not found | `mirrorOf` is `*`, so `pulp-releases` is sent to the cache. Exclude those ids. |
| A new snapshot is not picked up | `updatePolicy` `always` on the snapshots repository, or `mvn -U`. |
| Cache misses for a known artifact | The distribution has no pull-through remote, or the remote URL is wrong. |
