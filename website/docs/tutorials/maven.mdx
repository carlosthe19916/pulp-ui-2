# Maven repository manager

Set up Pulp the way you would set up Nexus or Artifactory for Maven: a cache of Maven Central, hosted repositories for your own releases and snapshots, and a Maven client that uses them for everything.

```text
mvn / gradle --> Pulp --+-- maven-central    pull-through cache --> Maven Central
                        +-- maven-releases   hosted
                        +-- maven-snapshots  hosted
```

| Nexus / Artifactory        | Pulp                                                                                                  |
| -------------------------- | ----------------------------------------------------------------------------------------------------- |
| Proxy (remote) repository  | Remote + repository + distribution with a **pull-through remote**                                     |
| Hosted (local) repository  | Repository + distribution; `mvn deploy` uploads to it                                                 |
| Release / snapshot policy  | Two repositories by convention; Pulp itself does not separate them                                    |
| Group (virtual) repository | Not available; list the repositories in `settings.xml` instead                                        |
| Staging and promotion      | Copy content between repositories; every change is a new [repository version](#versions-and-rollback) |
| "Set me up"                | **Client setup** snippet on distributions, **Install** snippet on packages                            |

## Prerequisites

- Pulp UI connected to a Pulp server with `pulp_maven`, signed in as a user who can create Maven repositories (see [Tutorials](./index.md#before-you-start))
- JDK 17 or later and Maven 3.9 or later
- The example projects in [`examples/maven`](https://github.com/carlosthe19916/pulp-ui-2/tree/main/examples/maven): `hello-lib`, a library you publish, and `hello-app`, which uses it

The URLs below are for the local backend (`http://localhost:5003`, domain `default`). Replace them with the ones your distributions show.

:::tip[In a hurry?]

`examples/maven/setup.sh` creates every Pulp object of steps 1 and 2 through the REST API, and `examples/maven/demo.sh` runs steps 3 to 5. See [Run the examples](./index.md#run-the-examples).

:::

## 1. Proxy Maven Central

Pulp caches Maven Central with three objects: a **remote** that knows the upstream URL, a **repository** that stores what was fetched, and a **distribution** that serves the repository and falls back to the remote for anything missing.

1. **Content Management → Remotes → Create remote.** Type **Maven**, name `maven-central`, URL `https://repo1.maven.org/maven2/`.

   ![Create Maven remote form](/img/tutorials/maven/remote-create.png)

2. **Repositories → Create repository.** Type **Maven**, name `maven-central`. Leave **Remote** empty: for Maven, the remote belongs on the distribution.
3. **Distributions → Create distribution.** Type **Maven**, name and base path `maven-central`, repository `maven-central`. Open **Pull-through caching** and pick the `maven-central` remote.

   ![Create Maven distribution form with a pull-through remote](/img/tutorials/maven/dist-create.png)

The distribution page shows the **Base URL** Maven reads from, with a ready-made **Client setup** snippet:

![Maven distribution details with the base URL and client setup snippet](/img/tutorials/maven/dist-detail.png)

Every artifact a client asks for is downloaded once, stored, and added to `maven-central` as a new repository version. It stays available if Maven Central is unreachable or if you later remove the remote.

## 2. Host your own packages

Create a repository and a distribution for each of `maven-releases` and `maven-snapshots`, as in step 1 but without a remote. Use the repository name as the base path.

You now have two URLs per hosted repository. They are easy to mix up:

| Purpose              | URL                                                          | Keyed by        |
| -------------------- | ------------------------------------------------------------ | --------------- |
| Read (resolve)       | `http://localhost:5003/pulp/content/default/maven-releases/` | Base path       |
| Write (`mvn deploy`) | `http://localhost:5003/pulp/maven/default/maven-releases/`   | Repository name |

The deploy URL is `<pulp>/pulp/maven/<domain>/<repository-name>/`. Without domains, drop `<domain>/`.

## 3. Configure Maven

Put this in `~/.m2/settings.xml`. It sends every Maven Central request to the Pulp cache, adds the hosted repositories, and stores the deploy credentials.

```xml title="~/.m2/settings.xml"
<settings>
  <servers>
    <!-- Deploy credentials: a Pulp user allowed to modify Maven repositories. -->
    <server>
      <id>pulp-releases</id>
      <username>admin</username>
      <password>password</password>
    </server>
    <server>
      <id>pulp-snapshots</id>
      <username>admin</username>
      <password>password</password>
    </server>
  </servers>

  <mirrors>
    <mirror>
      <id>pulp-central</id>
      <url>http://localhost:5003/pulp/content/default/maven-central/</url>
      <mirrorOf>central</mirrorOf>
    </mirror>
  </mirrors>

  <profiles>
    <profile>
      <id>pulp</id>
      <repositories>
        <repository>
          <id>pulp-releases</id>
          <url>http://localhost:5003/pulp/content/default/maven-releases/</url>
          <snapshots><enabled>false</enabled></snapshots>
        </repository>
        <repository>
          <id>pulp-snapshots</id>
          <url>http://localhost:5003/pulp/content/default/maven-snapshots/</url>
          <releases><enabled>false</enabled></releases>
          <snapshots><updatePolicy>always</updatePolicy></snapshots>
        </repository>
      </repositories>
    </profile>
  </profiles>

  <activeProfiles>
    <activeProfile>pulp</activeProfile>
  </activeProfiles>
</settings>
```

:::tip

Encrypt the passwords with [`mvn --encrypt-password`](https://maven.apache.org/guides/mini/guide-encryption.html). The example's [`settings.xml`](https://github.com/carlosthe19916/pulp-ui-2/tree/main/examples/maven/settings.xml) reads every value from environment variables instead, so you can run it with `mvn -s settings.xml` without touching `~/.m2`.

:::

## 4. Resolve dependencies through Pulp

Build `hello-lib`. Maven downloads its plugins and `commons-lang3` from the Pulp cache:

```bash
cd examples/maven/hello-lib
mvn package
```

```text
[INFO] Downloading from pulp-central: http://localhost:5003/pulp/content/default/maven-central/org/apache/commons/commons-lang3/3.17.0/commons-lang3-3.17.0.pom
[INFO] Downloaded from pulp-central: http://localhost:5003/pulp/content/default/maven-central/org/apache/commons/commons-lang3/3.17.0/commons-lang3-3.17.0.pom (31 kB at 638 kB/s)
...
[INFO] BUILD SUCCESS
```

In Pulp UI, open the `maven-central` repository: **Versions** grew by one version per cached file, and **Content → Browse** lists the cached packages.

## 5. Publish your package

`hello-lib/pom.xml` declares where `mvn deploy` uploads. The ids match the `<server>` entries above:

```xml title="hello-lib/pom.xml"
<distributionManagement>
  <repository>
    <id>pulp-releases</id>
    <url>http://localhost:5003/pulp/maven/default/maven-releases/</url>
  </repository>
  <snapshotRepository>
    <id>pulp-snapshots</id>
    <url>http://localhost:5003/pulp/maven/default/maven-snapshots/</url>
  </snapshotRepository>
</distributionManagement>
```

:::note

The example pom writes `${pulp.deploy.url}/maven-releases/`; its `settings.xml` sets `pulp.deploy.url`. Use whichever suits your team.

:::

Deploy a snapshot, then a release. Maven picks the repository from the version:

```bash
mvn deploy -Drevision=1.0.1-SNAPSHOT   # → maven-snapshots
mvn deploy -Drevision=1.0.0            # → maven-releases
```

```text
[INFO] Uploading to pulp-releases: http://localhost:5003/pulp/maven/default/maven-releases/org/example/pulp/hello-lib/1.0.0/hello-lib-1.0.0.jar
[INFO] Uploaded to pulp-releases: http://localhost:5003/pulp/maven/default/maven-releases/org/example/pulp/hello-lib/1.0.0/hello-lib-1.0.0.jar (2.8 kB at 4.3 kB/s)
[INFO] Uploading to pulp-releases: http://localhost:5003/pulp/maven/default/maven-releases/org/example/pulp/hello-lib/maven-metadata.xml
...
[INFO] BUILD SUCCESS
```

Open the `maven-releases` repository → **Content → Browse** and select a version. The package panel shows the POM details and an **Install** snippet for Maven and Gradle:

![hello-lib 1.0.0 in the maven-releases repository with its install snippet](/img/tutorials/maven/package.png)

## 6. Consume your package

`hello-app` depends on `org.example.pulp:hello-lib:1.0.0`. Remove the local copy so Maven has to fetch it from Pulp:

```bash
rm -rf ~/.m2/repository/org/example/pulp
cd ../hello-app
mvn -q compile exec:java
```

```text
Hello, Pulp!
```

## Going further

### Promote between repositories

Use a staging repository (for example `maven-staging`) as the deploy target, and copy what passes your checks into `maven-releases`. Open the target repository → **Actions → Add content…** → **From another repository**. Pulp copies references only: no file is uploaded or downloaded again. See [Promote Maven content](https://pulpproject.org/pulp_maven/docs/user/guides/promote/).

### Versions and rollback

Every deploy, cache fill or promotion creates a new repository version (**Versions** tab). To freeze what clients see, edit the distribution and choose **Serve → Repository version**. Point it back at **Repository** to follow the latest version again.

Pulp accepts a second deploy of an existing release version and replaces its files in a new repository version. If you need immutable releases, deploy to staging and promote.

### Access control

Reads from `/pulp/content/` are anonymous unless the distribution has a content guard (**Access** section). Deploys require a user with permission to modify the repository: create a deploy-only user and role in [Access management](../administration/roles-and-permissions.md) for CI, instead of reusing an administrator.

### Maintenance

The repository **Actions** menu has repair tasks for Maven: **Repair metadata** regenerates `maven-metadata.xml`, and **Build path index** / **Compact path index** maintain the index that speeds up lookups (**Path index** tab). See [Maven metadata](https://pulpproject.org/pulp_maven/docs/user/guides/metadata/).

## Troubleshooting

| Symptom                           | Cause and fix                                                                                                              |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `401 Unauthorized` on deploy      | No credentials: the `<server>` `id` must match the `distributionManagement` `id`.                                          |
| `403 Forbidden` on deploy         | The user can't modify that repository. Grant a Maven role in Access management.                                            |
| `404` on deploy                   | Deploy URL uses the base path or misses the domain. Use `/pulp/maven/<domain>/<repository-name>/`.                         |
| Your own artifacts aren't found   | `mirrorOf` is `*`, which also redirects `pulp-releases` to the cache. Use `central` or `*,!pulp-releases,!pulp-snapshots`. |
| A new snapshot isn't picked up    | Run Maven with `-U`, or keep `updatePolicy` `always` for the snapshots repository.                                         |
| Cache misses for a known artifact | The distribution has no pull-through remote, or the remote URL is wrong. Check the **Pull-through caching** section.       |

## Clean up

Delete the three distributions, then the three repositories, then the `maven-central` remote, each from its list's row actions. The stored artifacts are freed by Pulp's [orphan cleanup](https://pulpproject.org/pulpcore/docs/user/guides/reclaim-disk-space/) task.
