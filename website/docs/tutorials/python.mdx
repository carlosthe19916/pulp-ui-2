# Python repository manager

Set up Pulp the way you would set up Nexus or Artifactory for Python: a cache of PyPI, a hosted index for your own packages, and pip and twine pointed at Pulp.

```text
pip / twine --> Pulp --+-- pypi-proxy   pull-through cache --> pypi.org
                       +-- pypi-hosted  hosted
```

| Nexus / Artifactory        | Pulp                                                                                                                   |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Proxy (remote) repository  | Remote + repository + distribution with a **pull-through remote**                                                      |
| Hosted (local) repository  | Repository + distribution; `twine upload` uploads to it                                                                |
| Group (virtual) repository | One distribution serving a hosted repository **and** a pull-through remote, see [One index](#one-index-for-everything) |
| "Set me up"                | **Client setup** snippet on distributions, **Install** snippet on packages                                             |

## Prerequisites

- Pulp UI connected to a Pulp server with `pulp_python`, signed in as a user who can create Python repositories (see [Tutorials](./index.md#before-you-start))
- Python 3.9 or later
- The example projects in [`examples/python`](https://github.com/carlosthe19916/pulp-ui-2/tree/main/examples/python): `hello-lib`, a library you publish as `example-hello-lib`, and `hello-app`, which uses it

The URLs below are for the local backend (`http://localhost:5003`, domain `default`). Replace them with the ones your distributions show.

:::tip[In a hurry?]

`examples/python/setup.sh` creates every Pulp object of steps 1 and 2 through the REST API, and `examples/python/demo.sh` runs steps 3 to 6. See [Run the examples](./index.md#run-the-examples).

:::

## 1. Proxy PyPI

1. **Content Management → Remotes → Create remote.** Type **Python**, name `pypi-proxy`, URL `https://pypi.org/`, download policy **On demand**. Leave **Include projects** empty: a pull-through cache fetches only what clients ask for.

   ![Create Python remote form](/img/tutorials/python/remote-create.png)

2. **Repositories → Create repository.** Type **Python**, name `pypi-proxy`. Leave **Remote** empty.
3. **Distributions → Create distribution.** Type **PyPI**, name and base path `pypi-proxy`, repository `pypi-proxy`. Open **Pull-through caching** and pick the `pypi-proxy` remote.

The distribution page shows the index URL with a **Client setup** snippet:

![PyPI distribution details with the base URL and pull-through remote](/img/tutorials/python/dist-detail.png)

Every file pip downloads is fetched once from PyPI, stored, and added to `pypi-proxy` as a new repository version.

## 2. Host your own packages

Create a repository and a distribution named `pypi-hosted`, as in step 1 but without a remote. Keep **Allow uploads** on in the distribution.

| Purpose                | URL                                                      |
| ---------------------- | -------------------------------------------------------- |
| Read (`pip install`)   | `http://localhost:5003/pypi/default/pypi-hosted/simple/` |
| Write (`twine upload`) | `http://localhost:5003/pypi/default/pypi-hosted/legacy/` |

Both are `<pulp>/pypi/<domain>/<base-path>/` plus `simple/` or `legacy/`. Without domains, drop `<domain>/`. You don't need a publication: the distribution serves the repository directly.

## 3. Configure pip and twine

```ini title="~/.config/pip/pip.conf"
[global]
index-url = http://localhost:5003/pypi/default/pypi-proxy/simple/
extra-index-url = http://localhost:5003/pypi/default/pypi-hosted/simple/
```

```ini title="~/.pypirc"
[distutils]
index-servers = pulp

[pulp]
repository = http://localhost:5003/pypi/default/pypi-hosted/legacy/
username = admin
password = password
```

:::warning[Dependency confusion]

With `extra-index-url`, pip picks the highest version across both indexes. If someone publishes `example-hello-lib` 99.0 on PyPI, pip installs it. Use a single index ([One index for everything](#one-index-for-everything)), or names you have reserved on PyPI.

:::

The example's [`pip.conf`](https://github.com/carlosthe19916/pulp-ui-2/tree/main/examples/python/pip.conf) and [`.pypirc`](https://github.com/carlosthe19916/pulp-ui-2/tree/main/examples/python/.pypirc) hold the same settings; `demo.sh` passes them as environment variables.

## 4. Install through Pulp

Create a virtual environment and install the build tools. pip downloads them from the Pulp cache:

```bash
cd examples/python
python3 -m venv .venv && source .venv/bin/activate
pip install build twine
```

In Pulp UI, `pypi-proxy` → **Content → Browse** now lists `build`, `twine` and their dependencies.

## 5. Publish your package

```bash
HELLO_LIB_VERSION=1.0.0 python -m build -o dist hello-lib
twine upload -r pulp dist/*
```

```text
Uploading distributions to http://localhost:5003/pypi/default/pypi-hosted/legacy/
Uploading example_hello_lib-1.0.0-py3-none-any.whl
Uploading example_hello_lib-1.0.0.tar.gz
```

Open `pypi-hosted` → **Content → Browse** and select the package. The panel shows its metadata and an **Install** snippet:

![example-hello-lib in the pypi-hosted repository with its install snippet](/img/tutorials/python/package.png)

## 6. Consume your package

`hello-app` requires `example-hello-lib`, which in turn requires `rich` from PyPI:

```bash
pip install -r hello-app/requirements.txt
python hello-app/app.py
```

```text
Hello, Pulp!
```

`example-hello-lib` comes from `pypi-hosted`, and `rich` from the `pypi-proxy` cache.

## Going further

### One index for everything

A PyPI distribution can serve a repository and fall back to a pull-through remote for anything the repository doesn't have. Point a distribution at `pypi-hosted` and set its pull-through remote to `pypi-proxy`: one `index-url` then serves your packages and PyPI. For a project the repository has, Pulp lists only the repository's files and doesn't ask PyPI, which avoids dependency confusion.

The catch: files fetched from PyPI are added to `pypi-hosted` too, mixing cached and hosted packages in one repository.

### Mirror instead of cache

To sync a curated set ahead of time, set **Include projects** on the remote (for example `requests>=2.30`) and run **Actions → Sync** on the repository. Leave **Include projects** empty only if you mean to mirror all of PyPI.

### Versions, rollback and access control

Every upload or cache fill creates a new repository version (**Versions** tab). Edit the distribution and choose **Serve → Repository version** to freeze what clients see. Uploads require a user who can modify the repository: see [Access management](../administration/roles-and-permissions.md).

## Troubleshooting

| Symptom                                   | Cause and fix                                                                                                          |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `400 ... already exists in index`         | That file name is already in the repository. Bump the version; twine's `--skip-existing` isn't supported against Pulp. |
| `403` or `405` on upload                  | The user can't modify the repository, or the distribution's **Allow uploads** is off.                                  |
| `No matching distribution found` for PyPI | The proxy distribution has no pull-through remote, or the remote's **Include projects** excludes the package.          |
| Base URL shows the wrong host             | Set `PYPI_API_HOSTNAME` on the Pulp server to the URL clients use (see [Tutorials](./index.md#non-local-servers)).     |

## Clean up

Delete the two distributions, then the two repositories, then the `pypi-proxy` remote, each from its list's row actions. Stored packages are freed by Pulp's [orphan cleanup](https://pulpproject.org/pulpcore/docs/user/guides/reclaim-disk-space/) task.
