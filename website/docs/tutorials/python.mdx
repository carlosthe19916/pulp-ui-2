# Python repository manager

Two jobs. A pull-through cache of PyPI, and one index that serves your packages and falls back to PyPI. The second is how you avoid dependency confusion: if the repository already has the project, Pulp does not ask PyPI.

```text
pip / twine --> Pulp --+-- pypi-proxy   pull-through --> pypi.org
                       +-- pypi-hosted  your packages, optional PyPI fallback
```

You need Pulp with `pulp_python`, Python 3.9+, and [`examples/python`](https://github.com/carlosthe19916/pulp-ui-2/tree/main/examples/python). `setup.sh` creates a separate cache and a hosted index. URLs are the local backend, domain `default`. On another server, `PYPI_API_HOSTNAME` must be the URL clients use, or the base URL in the UI is wrong. See [Tutorials](./index.md#settings-the-local-backend-already-has).

You do not create a publication. The distribution serves the repository.

## A cache, and a hosted index

The pull-through remote belongs on the distribution. Leave **Include projects** empty on a pull-through remote: empty means "fetch what clients ask for."

| Object | What matters |
| ------ | ------------ |
| Remote `pypi-proxy` | URL `https://pypi.org/`, policy **On demand**, includes empty. |
| Repository `pypi-proxy` | No remote. |
| Distribution `pypi-proxy` | Repository `pypi-proxy`, pull-through remote `pypi-proxy`. |
| `pypi-hosted` | Repository and distribution, no remote. **Allow uploads** on. |

| Purpose | URL |
| ------- | --- |
| Read (`pip install`) | `http://localhost:5003/pypi/default/pypi-hosted/simple/` |
| Write (`twine upload`) | `http://localhost:5003/pypi/default/pypi-hosted/legacy/` |

Both are `<pulp>/pypi/<domain>/<base-path>/` plus `simple/` or `legacy/`.

```ini title="~/.config/pip/pip.conf"
[global]
index-url = http://localhost:5003/pypi/default/pypi-proxy/simple/
extra-index-url = http://localhost:5003/pypi/default/pypi-hosted/simple/
```

```ini title="~/.pypirc"
[distutils]
index-servers = pulp

[pulp]
repository = http://localhost:5003/pypi/default/pypi-hosted/legacy/
username = admin
password = password
```

:::warning[Dependency confusion]

`extra-index-url` makes pip pick the highest version across both indexes. A public `example-hello-lib` 99.0 would win. Prefer the single index below, or a project name you have reserved on PyPI.

:::

```bash
cd examples/python
python3 -m venv .venv && source .venv/bin/activate
pip install build twine
HELLO_LIB_VERSION=1.0.0 python -m build -o dist hello-lib
twine upload -r pulp dist/*
pip install -r hello-app/requirements.txt
python hello-app/app.py
```

`twine --skip-existing` is not supported. Bump the version.

## One index

Point the hosted distribution at repository `pypi-hosted` and set its pull-through remote to `pypi-proxy`. One `index-url` then serves your packages and PyPI. For a project the repository has, Pulp lists only that repository's files.

The catch: files fetched from PyPI are added to `pypi-hosted` too, so cached and hosted packages share one repository.

## A curated mirror

To sync a set ahead of time, put the specifiers on the remote and sync the repository. **Include projects** empty on a **sync** means all of PyPI. Empty on a pull-through cache means the opposite.

| Field | Effect |
| ----- | ------ |
| Includes | Only these projects, with specifiers (`django>=4.2`). |
| Excludes | Projects to leave out. |
| Package types | `sdist`, `bdist_wheel`, and so on. |
| Exclude platforms | Drop wheels you do not need, such as Windows. |
| Latest versions to keep | The N newest releases of each project. `0` keeps all. |
| Include pre-releases | Off leaves them out. |

A **blocklist** on the repository skips a project on sync and refuses it on upload, even when it exists on PyPI. A block is a project name, optionally a version, optionally one filename. Removing the block allows the next sync or upload.

If you already have a [Bandersnatch](https://pypi.org/project/bandersnatch/) config, **From Bandersnatch config** on the remote create menu builds a Python remote from `bandersnatch.conf`. Read the generated includes and excludes before you sync. Bandersnatch and Pulp do not spell every filter the same way.

## What the UI shows and does not do

**Repair metadata** regenerates each package's metadata in place. The repository version does not change. Re-downloading a missing file is [repair](../concepts/disk.md), a different operation.

:::info[Not yet in Pulp UI]

Yanking a release (do not install unless pinned), the way PyPI does. Pulp stores yanks and the repository's **Yanked** section lists them. Yanking itself is the Pulp API today. See [pulp_python](https://pulpproject.org/pulp_python/).

:::

Vulnerability reports do not change content. Turn **Scan for vulnerabilities** on the remote to scan after each sync, or scan one repository version on demand. To keep a package out, block it.

Uploads need a user who can modify the repository. See [Who can push](../concepts/access-control.md).

## Troubleshooting

| Symptom | Cause and fix |
| ------- | ------------- |
| `400 ... already exists in index` | That filename is already in the repository. Bump the version. |
| `403` or `405` on upload | The user cannot modify the repository, or **Allow uploads** is off. |
| `No matching distribution found` for a public package | The distribution has no pull-through remote, or **Include projects** excludes it. |
| Base URL shows the wrong host | Set `PYPI_API_HOSTNAME` to the URL clients use. |
