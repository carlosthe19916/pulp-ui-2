# APT repository manager

Mirror a slice of Debian or Ubuntu, or publish `.deb` packages you build. The choice that matters is the publication.

```text
apt --> Pulp --+-- apt-upstream  on-demand mirror of one suite
               +-- apt-hosted    packages you upload, structured publication
```

There is no pull-through cache. You sync. **On demand** downloads the indexes now and each package on first install. A wrong distribution, component or architecture fails the sync. **Ignore missing package indices** skips an index the upstream does not have. Leave **GPG public key** set on a real remote so Pulp verifies `Release` on every sync.

[`examples/deb`](https://github.com/carlosthe19916/pulp-ui-2/tree/main/examples/deb) mirrors `http://nginx.org/packages/debian/` (`bookworm`, component `nginx`, `amd64`) because it is small. For Debian itself use `http://deb.debian.org/debian/`, limited to the suites you need. The remote URL is the directory that contains `dists/`.

## Structured or verbatim

| Publication | What clients get | Use it when |
| ----------- | ---------------- | ----------- |
| APT | Pulp rebuilds `Release` and `Packages` from the content in the repository. **Auto-publish** creates this. | You upload your own packages, or you want a suite you curate. |
| APT (verbatim) | The upstream files, unchanged. | You want a faithful mirror of that slice, including upstream metadata. |

Both types exist on the publication create form. The structured form can also publish a simple `default` distribution that contains every package.

## Publish your own package

A hosted repository with **Auto-publish**, no remote, and a distribution. Upload sets **Distribution** and **Component**. Those two fields are the path: `dists/stable/main/`.

```text title="/etc/apt/sources.list.d/pulp.list"
deb [trusted=yes] http://localhost:5003/pulp/content/default/apt-upstream/ bookworm nginx
deb [trusted=yes] http://localhost:5003/pulp/content/default/apt-hosted/ stable main
```

`[trusted=yes]` is for an unsigned `Release`. Select a [signing service](../concepts/operating.md#signing) on the repository to sign `Release`, then drop `trusted=yes` and add `signed-by=`.

```bash
cd examples/deb
dpkg-deb --root-owner-group --build hello build/hello-pulp_1.0.0_all.deb
```

There is no `apt` command to publish. Upload the `.deb` with distribution `stable` and component `main`.

Dependencies such as `libc6` still come from the machine's Debian sources unless you mirror those suites too and replace the machine's sources.

Copy into a release suite copies references. Advanced copy brings dependencies along. Point the distribution at a repository version or an older publication to freeze the suite. See [What clients see](../concepts/what-clients-see.md).

## Troubleshooting

| Symptom | Cause and fix |
| ------- | ------------- |
| `404` for `Release` | No publication. Auto-publish, or publish. |
| `The repository is not signed` | `[trusted=yes]` for a test, or sign and set `signed-by=`. |
| The uploaded package is not found | `sources.list` uses a different distribution or component than the upload. |
| `held broken packages` | A dependency is not in any configured source. Mirror Debian, or keep the machine's sources. |
| Sync fails on missing indices | The remote names a distribution, component or architecture the upstream does not have. |
